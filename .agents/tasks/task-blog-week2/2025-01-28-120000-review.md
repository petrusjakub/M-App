# Week 2 content rewrite with formatting, images, and CTA icons

The HTML accordion page has been completely rewritten: all 21 articles now carry Week 2 topics (MiUltimate Healthcare, passive income, education planning, critical illness, ProActive Plus, etc.) presented as HTML-escaped code blocks inside each accordion panel. The page shifts from rendering articles directly to displaying copyable HTML source that the author can paste into WordPress. CTA buttons in both the header and article bodies embed inline SVG icons (info circle for the web link, WhatsApp logo for WA). Each article carries exactly 20 hashtags and one Unsplash `<img>` reference inside the code block. Writing style is emotional storytelling in casual Indonesian with reflective questions.

**Watch for:** Images exist only inside HTML-escaped `<code>` blocks and will not render visually on the accordion page itself (confirmed). The clipboard API calls have no fallback for older browsers or insecure contexts (confirmed). Tags are space-separated in `data-tags` but the spec asked for comma-separated words (likely mismatch with "dipisah koma").

## High-level view

The page now functions as a content-management dashboard rather than a reader-facing blog — 21 accordion items, each storing article HTML as escaped source inside a `<pre><code>` block with three copy buttons (title, article HTML, tags). Formatting tags and images exist as source text only; nothing renders visually on this page.

The SVG icons use a circle+question-mark `<text>` element for the info button and a path-based WhatsApp logo. Both render in the page header but appear only as escaped text inside article code blocks — correct for the copy-paste workflow, invisible when just browsing the accordion.

The tag specification asks for "20 tag yang dipisah koma per masing masing kata" — the implementation delivers 20 hashtags per article but separates them with spaces and uses multi-word compounds (#AsuransiKesehatan, #KesehatanKeluarga) rather than comma-separated single words.

<summary>Issues (4)</summary>

1. **Images not rendered on page** — All `<img>` tags are inside HTML-escaped code blocks (`&lt;img ...&gt;`), so no images actually display when the accordion page is viewed. If the intent is for images to be visible to someone browsing the page, they need to be outside the `<code>` block.
2. **No clipboard fallback** — `navigator.clipboard.writeText` requires HTTPS or localhost. The Week 1 version had a `fallbackCopy` function using `document.execCommand('copy')` which was removed. Users on HTTP or older browsers will get silent failures with no error feedback.
3. **Tag separator mismatch** — The requirement says "dipisah koma" (comma-separated) but `data-tags` uses space-separated `#Word` format. If the copy target expects `#tag1, #tag2, #tag3`, the current output won't match.
4. **Multi-word hashtags vs single-word requirement** — The spec says "per masing masing kata" (each word individually). Tags like `#AsuransiKesehatan`, `#BiayaRumahSakit`, `#PerlindunganMaksimal` are compound words, not single words.

## Content architecture shift: code-display dashboard

Each accordion panel wraps article content in a `<pre class="code-block"><code>...</code></pre>` block displaying HTML-escaped source. The page serves as a staging tool, not a publication endpoint. The consequence is that formatting tags (`<b>`, `<i>`, `<u>`, `<mark>`) and images (`<img>`) exist only as text inside the code block. A visitor to this HTML page sees raw HTML source in a dark-themed code pane, not styled prose or rendered images. If the page doubles as a preview for stakeholders or prospective readers, this creates a UX gap where none of the "efek bold/italic/underline/stabilo" or images are visually demonstrated.

## Clipboard API without fallback

Week 1 had a robust clipboard implementation with a `fallbackCopy` function using `document.execCommand('copy')` for insecure contexts. Week 2 replaces this with three specialized functions (`copyTitle`, `copyArticle`, `copyTags`) that call `navigator.clipboard.writeText(...).then(...)` without a `.catch()` handler and without the textarea fallback. On HTTP origins (common for local file:// or non-HTTPS deployments), `navigator.clipboard` is undefined and the code will throw. Even on HTTPS, the promise rejection is unhandled — a denied permission silently fails with no user feedback.

## Tag format and separator

The `data-tags` attribute stores tags as `#Word1 #Word2 #Word3 ...` (space-separated). Pressing "Copy Tags" copies this string verbatim. The user's requirement specifies "dipisah koma" (separated by commas). Whether the final destination (WordPress tags input) accepts space-separated hashtags or needs comma-separated bare words is context-dependent, but the literal requirement is commas.

Additionally, "per masing masing kata" (each individual word) suggests single-word tags. Implementations like `#BiayaRumahSakit` or `#KesehatanKeluarga` are compound. This may be an acceptable interpretation (hashtag convention) or a mismatch depending on the author's intended use in WordPress tag fields.

## Accordion semantics regression

The old code used `<article>` elements for each accordion item; the new code uses generic `<div>` elements. Screen readers and search engines benefit from semantic `<article>` landmarks for repeated content blocks. Minor but free to fix.
